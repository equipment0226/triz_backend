# 분석 검증과 수정

2026-10-08 변경. 필수 통과 대상은 기능분석을 포함한 S3 분석·S4 문제정의다. 인테이크는 정보가 부족하면 먼저 사용자에게 확인하는 기존 흐름을 유지한다. 검증기의 점수 계산과 수정 지시 보존은 공통 에이전트에 적용한다.

## BASIC의 의미

이 서비스의 `rank=BASIC`은 **사용자가 확정한 시스템 경계에서 본래 수행해야 하는 대표 유익 기능 하나**를 뜻한다. 수행 주체가 처리 대상의 어떤 속성을 변화시키거나 유지하는지 명시해야 한다. 개선 목표·고장 현상·유해 입력·중간 지원 작용을 주기능으로 대체하지 않는다. 선택 경계가 하위 모듈이면 그 모듈의 목적을 판단하며 상위 장비 목적을 강요하지 않는다.

이것은 앱의 저장 규약이다. MATRIZ의 [basic function](https://wiki.matriz.org/knowledge-base/triz/problem-solving-tools-5807/function-cost-analysis-7189/function-analysis-5611/function-modeling-5810/function-ranking-5941/basic-function-5722/)은 구성요소가 처리 대상에 수행하는 유익 기능으로 복수일 수 있다. 앱의 단일 BASIC과 일반 TRIZ 정의를 구분한다. 독립된 필요 출력이 여러 개면 대표 선정 이유와 나머지 기능도 보존한다.

## 검증에서 저장까지

1. 생성기에 확정 경계·사용자 수정·관측 출처·선행 분석과 요소별 정의를 전달한다.
2. 코드가 전체 JSON 형식, 저장 스키마, BASIC의 유익성·개수, 참조 ID, 물질–장 구조, 모순 파라미터 등을 확인한다.
3. 독립 검증기가 경계에 맞는 주기능, 물질과 장의 역할, 관측과 가설, 동일 속성의 상반 요구, 기능 보존 등을 평가한다.
4. `required: true`인 기준은 가중 평균과 별개로 `min_score`를 충족해야 한다. 명시적 REVISE/REJECT, 미해결 수정 지시, 요소별 결함을 높은 총점으로 덮어쓰지 않는다.
5. 검증기의 `element_findings`는 경로·결함·수정 제안·근거·기준 ID를 담는다. 생성기는 해당 요소와 의존 요소를 고쳐 **전체 JSON**을 반환한다. 정당한 삭제·교체는 허용하지만 부분 수정본의 최상위 필드 누락은 거부한다.
6. 수정본 전체를 다시 구조·의미 검증한다. 통과한 결과만 typed state에 반영한다. 필수 분석이 수리 한도 안에 통과하지 못하면 FAILED로 기록하고 다음 단계 실행을 중단한다.

검증 비활성, 기준 누락, 불완전한 채점, 비유한 점수, 모델 호출 실패를 PASS나 기본값으로 처리하지 않는다. 과거에 저장된 기능모델이라도 BASIC이 없거나 유해·중복·참조 불능이면 S4 호출 전에 차단한다.

## 요소별 기준

| 요소 | 주요 확인 사항 |
|---|---|
| 9-Windows | 9개 칸, 시간·계층의 일관성, 미래 가설과 현재 관측 구분 |
| 기능모델 | 대표 유익 BASIC, 도구·대상·속성·경계, 처리 대상 연결, 간선 참조 |
| 물질–장 | 실제 물질/장의 역할, 구조적 누락과 효과 부족의 구분 |
| 자원 | 확인·가정·신규 구분, 가용 조건과 제약, 없는 자원은 사유 기록 |
| CECA | 손실과 연결된 비순환 인과, 관측 근거, 가설의 반증 조건; 깊이 때문에 원인 생성 금지 |
| 발견 제약 | 미확인 도메인 조건은 soft 가설, 확인된 금기는 실제 HARD 제약 ID 참조, 기존 ID 재정의 금지 |
| IFR | 유익 기능 보존, 불리한 수단을 목표로 고정하지 않음, 실제 제약 충돌 구분 |
| 기술적/물리적 모순 | 같은 조치의 두 성능 간 인과 / 동일 요소·동일 속성의 상반 요구 |
| 트리밍 | 실제 요소 제거, 필요한 유익 기능의 이전·자기수행·필요 소멸 |
| 핵심 문제 | 실제 모순 ID, 선정과 탈락의 중복 금지, 미선정 이유 |

적용할 수 없는 분석 결과를 개수 목표 때문에 발명하지 않는다. 빈 자원·물리적 모순은 미적용 사유를 보존하고, 근거 있는 모순이 전혀 없으면 후속 해법 생성 전에 보완을 요청하는 상태로 중단한다.

## 지식과 예시

S3/S4 산출물에 명시한 표준 형식의 `CON-xxxxxxxx` 제약 ID는 현재 제약 집합과 대조한다. 제약 발견 단계에서 명시적으로 새로 선언한 ID만 자체 참조를 허용한다. S5 표준해에서도 제공된 코드·물질장 그래프가 유효하지 않으면 수리 후 FAILED로 중단한다. S6의 보완 후보 보존과 후속 품질 선별은 유지한다.

`analysis_guidance.py`와 `knowledge/analysis_guidance_v1.json`은 공식 출처에 근거한 정의와 합성 정답·오답 대조 예시를 제공한다. 분석 단계·문제 유형·선택 경계에 따라 최대 한 개의 관련 예시를 생성기와 검증기에 동일하게 전달한다. 운영 프로젝트의 답을 검색해 복사하는 방식이 아니며 외부 검색이나 추가 모델 호출이 없다. 출처와 버전을 카탈로그에 기록한다.

이 예시와 의미 검증은 정확성을 높이는 장치이며 전문 분야의 사실 정확성을 보장하지 않는다. 서로 다른 속성을 PC로 묶는 등의 의미 오류는 JSON 검사만으로 증명할 수 없다. 저장 이력의 코드 재검사 결과와 새 모델 출력의 품질 평가는 구분한다.

## 재개·캐시·이력

과거 실행의 frozen bundle, 모델 설정, 사용량 및 원본 분석을 덮어쓰지 않는다. 재실행할 때 최신 필수 기준과 버전이 붙은 추가 지침을 적용한다. 새 bundle에는 검증 계약과 지식 버전·관련 소스 해시를 기록한다. 캐시를 쓰기 전 현재 검사기와 마지막 검증을 재확인하고 계약 변경 시 캐시 키가 바뀐다.

운영 이력의 일괄 재분석·자동 수정은 이 변경에 포함되지 않는다. 오프라인 회귀는 모델 응답을 대체하고 네트워크를 차단한다. 변경된 분석·검증 코드 테스트는 `pilot/`에서 실행한다:

```powershell
python -m pytest tests/test_analysis_checks.py tests/test_analysis_guidance.py tests/test_verification_contract.py tests/test_pipeline_quality.py -q
```
