# Introduction과 보고서 도식의 디자인 대응

`frontend/src/components/GuideVisual.jsx`의 색상·카드·분기 구성을 보고서 SVG에 적용한다. 보고서의 문구·분석 수치·노드·관계·방향·유해 작용 여부를 바꾸지 않는다. Introduction에 있는 학습용 예시를 보고서 데이터로 복사하지 않는다.

| 보고서 | 디자인 기준과 실제 데이터 처리 |
| --- | --- |
| 기능 모델 | 녹색 유익 작용, 갈색 유해 점선, 밝은 카드. 실제 구성요소와 관계를 유지한다. |
| 기술적 모순 | 조치를 위에, 개선되는 특성과 악화되는 특성을 아래에 배치한다. |
| 물리적 모순 | 동일한 요소·특성을 위에, 반대 상태와 각각의 요구 이유를 아래에 배치한다. |
| Su-Field 분석 | F–S2–S1 삼각 배치. 저장된 연결만 표시하며 S3에 연결을 추정해서 추가하지 않는다. |
| 인과사슬·ARIZ | 실제 관계로 계층을 배치한다. 순환 또는 복잡한 모델은 일반 배치를 사용하며 노드를 생략하지 않는다. |
| 모순행렬 결과 | 실제 개선·악화 파라미터와 추천 원리를 카드로 연결한다. 사용하지 않은 행렬 셀을 임의로 채우지 않는다. |
| 분리원리 | 2열 구분선과 적용 가능 항목의 녹색 음영. 적용 불가 항목도 설명을 유지한다. |
| 자원·IFR·트리밍·FOS·진화 방향·해결안 | 밝은 바탕과 녹색 계열 카드·구분선을 적용한다. 데이터에 없는 중앙 기능이나 단계 사이의 인과 관계를 만들지 않는다. |
| S-커브 | Introduction의 선·축·색상을 적용하고 기록된 성숙 단계를 유지한다. 분석에 없는 미래 곡선을 추가하지 않는다. |
| 평가 사분면 | Introduction의 2×2 격자와 색상. 기존 Markdown의 점수 계산·좌표를 공유하며 겹치는 점을 이동시키지 않는다. |
| 표준해 적용 | 이미 통합한 `standard_application_diagrams.py`를 유지한다. 표준해별 참조 문양과 실제 해결책의 물질·장·연결을 결합한 하나의 그림이다. |

`report_diagram_style.py`는 위치와 색상을 담당하고 `visuals.py`는 기존 데이터로 SVG를 그린다. `presentation.view()`와 다운로드 HTML이 같은 SVG를 사용한다. 저장된 프로젝트를 다시 조회하면 새 디자인이 적용되며 분석을 재실행하거나 저장 데이터를 변환할 필요가 없다.

## 검증과 재현

`test_report_introduction_design.py`는 이전 렌더 방식과 노드·관계·내용을 비교하고 원본 상태의 불변성, 실제 분기 배치, 연결 없는 S3 보존, 긴 카드와 범례, 평가 좌표를 확인한다. `test_report_layout.py`와 `test_standard_diagrams.py`의 기존 검사도 유지한다.

로컬 시각 검토는 아래 명령으로 재현한다. 합성 보고서만 생성하며 실제 사용자 프로젝트나 DB에 쓰지 않고 LLM을 호출하지 않는다.

```powershell
.venv/Scripts/python.exe -X utf8 deploy/preview_report_introduction.py
cd frontend
node scripts/verify-report-introduction-design.mjs
```

두 번째 명령은 공개 앱의 코드를 불러오되 해당 브라우저의 보고서 응답만 로컬 합성 자료로 대체한다. 실제 운영 보고서 검증과 구분한다. PC 1,440px·모바일 390px, 확대·스크롤, 카드 내부 텍스트, HTML PDF 출력을 확인한다. 결과는 `pilot/data/report-introduction-review/`에 저장하며 배포 파일에는 포함하지 않는다.
