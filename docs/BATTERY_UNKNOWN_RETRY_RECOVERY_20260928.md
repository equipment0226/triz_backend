# 배터리 H 트랙 미확인 호출의 명시적 복구

대상: `run-a702a133056f34455790fe2e73f8a2dc`, 무가압 전고체 배터리 계면 밀착과 강성-유연성 상충 해결.

## 운영 진단

2026-09-28 재조회에서 같은 제목의 프로젝트는 한 건이었다. S5_SOLVE의 H_EFFECTS 작업은
08:07:41 UTC(17:07:41 KST)에 DeepSeek 요청을 시작했으나, 08:07:47 UTC의 이전 컨테이너
종료와 겹쳐 응답과 사용량을 저장하지 못했다. 최초 종료 타임라인은
`BATTERY_RESTART_FIX_20260928.md`에 기록되어 있다.

미확인 작업은 `task-83d61adb576fdfd59617dbbce9788fea6824cd9f7f4d84089d7db1ec9b8b`이다.
task 결과와 attempt 응답/사용량이 모두 없으므로 실제 청구액을 로컬 기록으로 확정할 수 없다.
이전 lease 만료 처리에서는 task만 UNKNOWN으로 바뀌고 attempt는 RUNNING으로 남는 불일치도 있었다.

완료 트랙 A/B/C/E/F/G와 완료 호출 35건은 유지되어 있다. 확인된 비용은 $0.188722,
미확인 비용 예약은 $0.133379, 프로젝트 한도는 $2.00이다. 예약은 확정 청구액이 아니다.
직전 배포(7fe4bae)의 사전 차단이 작동하여 최근 재개 시도에서는 추가 호출 없이 동일 UNKNOWN을 차단했다.
새로운 공급자 장애가 확인된 것이 아니라, 기존 미확인 호출을 복구할 경로가 없는 상태다.

## 수정

- 소유자만 호출할 수 있는 `/api/runs/{run_id}/ax/usage-recovery` 조회/승인 API를 추가했다.
- 화면에서 이어서 실행을 누르면 미확인 예약과 추가 예약 상한을 표시하고, 추가 비용 가능성에
  명시적으로 동의한 경우에만 복구 승인을 기록한 뒤 기존 이어서 실행을 호출한다. 취소하면 호출하지 않는다.
- 승인에는 프로젝트 소유자, 실행 버전, 분석 입력 버전, 원본 task 및 예약 상한을 기록한다.
  승인 API 자체는 유료 모델이나 파이프라인을 호출하지 않는다.
- 원래 UNKNOWN과 비용 예약은 그대로 남기고, 같은 요청에 대해 결정적인 ID를 갖는 복구 task를
  한 번만 만든다. 완료 결과는 재사용한다. 복구 task도 UNKNOWN이 되면 추가 연쇄 재시도를 차단한다.
- 프로젝트 예산과 검토 예약을 유지한다. 입력 버전 변경, 소유자 불일치, 예산 부족, 승인 상한 초과를 차단한다.
- 승인받은 원본 UNKNOWN만 stage 사전 차단에서 제외한다. 승인되지 않은 UNKNOWN은 계속 차단한다.
- lease 만료 및 검증된 사용량 정산 시 attempt 상태도 task와 함께 갱신한다.

## 검증 및 적용 범위

유료 공급자 호출 없이 격리된 SQLite와 모의 API로 검증한다. 복구 테스트는 소유권/승인/예산,
중복 및 동시 요청, 두 번째 UNKNOWN 차단, 지연 정산, 실제 gateway의 결과 재사용,
pipeline 사전 차단을 다룬다. 프런트엔드 테스트는 동의 취소, 승인 실패, 동의 후 재개 순서를 다룬다.

결과: 백엔드 관련 테스트 총 160개 통과(159개 회귀 묶음 + 추가 gateway 복구 사례 1개).
복구 전용 테스트 파일 13개가 모두 통과했다. 프런트엔드 로직 6개와 실제 브라우저 흐름 1개가
통과했으며 Vite production build도 성공했다. 브라우저 테스트의 최초 실패는 모의 프로젝트의
단계 목록 누락이었고, 실제 API 형태에 맞춰 테스트 데이터를 보완한 뒤 통과했다.
운영 읽기 전용 재조회에서 원본 H 요청의 분석 입력 버전이 현재 프로젝트와 일치함도 확인했다.

이번 디버깅에서는 운영 데이터를 수정하거나 실제 H 재시도를 실행하지 않았다. 수정은 로컬 소스에
준비하며, 적용하려면 백엔드와 프런트엔드를 함께 배포한 뒤 프로젝트 소유자가 재시도에 동의해야 한다.
기존 예약을 임의로 0원 정산하거나 H를 건너뛰어 완료 처리하지 않는다.
