## 2. 원전 전수 검토

1차 근거는 [Altshuller Foundation 러시아어 원전](https://www.altshuller.ru/triz/standards.asp), 교차 자료는 [MATRIZ SIS](https://wiki.matriz.org/docs/triz/problem-solving-tools-5890/substance-field-modeling/standard-inventive-solutions/)이다. 두 자료의 각 번호 본문을 읽었으며, 클래스 1·2 원전 도식 29개와 클래스 3·4 원전 도식 7개·MATRIZ 도식 8개를 열어 관계를 확인했다. 클래스 5 해당 절에는 두 자료 모두 별도 도식이 없었다. 기존 JSON과 ROWS는 근거로 사용하지 않았다.

부모 76개(13/23/6/17/17), 공식 하위 항목 11개, 번호 없는 분기 76개, 발전 순서가 있는 부모 13개를 보존한다. 공식 하위 번호는 `1.1.8.1–2`, `5.1.1.1–9`이며 부모 코드 집합에는 들어가지 않는다. 임의의 공식 번호는 만들지 않았다. 기존 필수 필드 타입과 최상위 구조를 유지했다. 제목은 의미 오류가 있는 2.2.2, 2.3.1, 2.3.2, 2.4.9, 4.1.3만 수정하고 나머지는 유지했다.

`description/transformation/conditions`는 원전 의미를 한국어로 재서술했다. `limitations`는 편집상 공학 주의이며 원전의 필수 조건과 구별한다. `verified`는 출처 대조만 의미한다. 실제 문제의 조건 충족, 재료 실험, 개별 특허의 유효성·재현성을 확인한 것이 아니다. 상세 그림 URL과 항목별 차이는 각 `source_review`에 보존했다.

## 4. 기존 흐름·MCP 호환성

S3 `su_field` → `K.standard_hints` → 저장된 `standard_class_hint` → Track C의 `K.candidate_standards` → `K.standards_block` → 기존 T2 호출 → `bind_standard`·`check_standards` → standard_apps/raw_ideas → digest·저장/복원·보고서 연결을 확인했다. Track C의 Su-Field 최대 2개, 후보 기본 12개, 적용안 최대 6개, 기존 변수명·rubric·호출 구조를 유지한다. 새로운 상위 제약 입력이나 effect 배열은 없다.

선택된 부모에 있는 모든 하위 방법과 분기를 렌더링한다. 5.1.1의 9개 방법과 1.1.8의 2개 방법을 자르지 않는다. standard_code에는 부모만 허용하며 하위 방법은 기존 transformation/mechanism/idea에 설명한다. 하위 번호나 없는 번호를 부모로 자동 보정하지 않는다. 측정의 신호 경로·복합 구조를 S2-F-S1/S3 삽입으로 강제하지 않는다. 조건에 맞는 안이 없을 때 빈 applications와 사유를 반환하는 경로를 유지한다.

ARIZ Part5는 같은 후보·렌더링·바인딩 함수를 통해 상세를 받는다. Part5 전용 프롬프트, 단계, 필수 스텝, 토큰 설정, Part6 진행 계약은 변경하지 않았다.

MCP 직접 호출은 기존 노드를 실행하지 않으므로 두 prompt_id에 한정해 보완했다.

- `triz_s3_sufield`: 반환 모델의 standard_class_hint만 공통 규칙으로 갱신한다. S1/S2/S3/F·completeness/effect와 GlobalState 분석·단계를 덮어쓰지 않는다.
- `triz_s5_track_c`: standards_block의 명시적 부모 코드 목록(공백/쉼표 구분) 또는 기존 형식의 부모 제목 행을 해석한다. 지정된 subset·순서는 유지하고 내용은 로컬 정본으로 다시 만든다. 모호한 산문, 하위 코드, 없는 번호, 유효 후보 없음은 모델 호출 전에 거절한다. 빈 문자열은 기존 변수의 S1/S2/F/자원으로 공통 후보 선별을 사용한다.
- 결과는 bind_standard 후 check_standards로 검사하며 부적합 결과는 ValueError로 거절한다. 직접 호출에 checker/rubric을 새로 붙여 유료 repair 호출을 만들지 않고 기존 호출 뒤 로컬 검사한다. 노드와 직접 도구의 전체 품질 검토 정책이 같아졌다는 뜻은 아니다.
- 동일 후보·정규화 문맥에서 부모 코드와 정본 조건·제목·출처가 일치한다. 다른 문맥의 후보까지 같게 강제하지 않는다. 도구명, `(run_id, variables)`, 필수 변수, `{artifact, run_id}`, 잠금·저장·인증 계약과 다른 prompt 도구를 유지한다.

## 6. 원전의 차이와 남은 범위 밖 항목

원전 본문 접근 불가로 남은 부모 항목은 없다. 다음 해석 차이와 예시의 한계는 제거하거나 검증 완료로 위장하지 않았다.

- 3.1.1·3.2.1: 발전 여력을 소진해야만 전이 가능하다는 전제를 제거했다. 원전은 어느 발전 단계에서든 전이를 허용한다.
- 4.3.3: 원전 규칙은 고유주파수 변화인데 인용 예시는 진폭 변화를 말한다. 규칙과 사례를 구분했다. 4.4.5는 MATRIZ가 생략한 기존 Fe-Field 측정계 전제를 유지했다.
- 5.1.1.8: 철 oxalate 예시의 괄호 속 산 명칭 불일치는 원전 예시 문제로 기록했다. 공식 방법은 화합물로 도입한 뒤 첨가제를 방출하는 것이다.
- 5.5.3: 원전의 whole/non-whole 표현은 엄밀한 범용 입자 분류 정의가 아니다. 가까운 구조 수준과 원문이 든 과잉/부족 입자 범위를 보존하고 새로운 물리 법칙으로 일반화하지 않았다.

범위 밖 운영 파일은 지시문에 따라 자동 수정하지 않았다.

1. **정적 자료실 동기화:** `frontend/src/pages/MaterialLibrary.jsx`는 `frontend/src/data/knowledge.json`을 읽고 `StandardsExplorer.jsx`는 정적 SVG를 읽는다. 이 사본은 새 정본과 자동 동기화되지 않는다. 특히 SVG 제목이 다른 번호는 **2.2.2, 2.3.1, 2.3.2, 2.4.9, 4.1.3**이다. 따라서 정적 자료실까지 반영하려면 별도 자산 재생성이 필요하며 이번 결과를 프런트 전체 반영 완료라고 보지 않는다.
2. **기존 개념 도식의 이론 범위:** `pilot/triz/standard_diagram_specs.py`의 1.2.4는 S2를 빠뜨려 직접 접촉 보존 관계를 표현하지 못한다. 2.2.2는 도구 분할을 대상 일반 분할로 넓힌다. 2.3.1/.2는 의도적 비정합이 없고 2.3.1은 불일치를 항상 유해로 표시한다. 2.4.9는 장 구조화와 물질 구조 형성 분기를 혼합하며 구조화된 열장 분기가 없다. 2.4.11은 전류 간 상호작용 대안이 없다. 개별 문제에서 저장한 resulting_model 관계는 유지되지만, 참고 개념 도식의 포괄성은 별도 보완 과제이다.
