## 발견한 저장·복구 문제

S5는 완료 트랙을 메모리상 부모 상태에 합치지만 마지막 단계 저장 전까지 DB의 run_states가 오래된 상태일 수 있었다. 이 프로젝트의 화면용 상태는 23번째 단계에서 멈춰 있었지만, 별도 steps/event/task journal에는 29번째 단계와 여섯 트랙 완료가 남아 있었다. 화면에는 완료 트랙이 PENDING, 비용이 $0.105173으로 표시될 수 있는 상태였다.

기존 orphan 복구는 일반 중단 문구만 기록하고 상세 단계 journal과 비용을 복구하지 않았다. 진행 중 과금 예약도 즉시 UNKNOWN으로 정리하지 않았다.

## 변경 사항

- 완료된 S5 트랙 묶음을 합친 직후 부모 상태를 저장한다. 병렬 근거 검색 결과를 잃지 않도록, 별도 트랙 상태의 저장은 부모 상태에 합친 후 수행한다.
- 단계 시작도 journal에 기록한다. 종료 기록만 있던 경우의 진행 중 단계 누락을 방지한다.
- 실행 워커가 사라지면 상세 단계 journal을 다시 합친다. 확정된 완료 결과를 유지하고 완료 여부를 확인하지 못한 RUNNING 단계만 실패 이력으로 남긴다.
- 해당 run lock 및 AX head lock 안에서 실행 중 과금 예약과 attempt를 UNKNOWN으로 전환하고 감사 이벤트를 기록한다. 예약은 유지하며 비용 표시는 journal 정산값으로 맞춘다.
- 호출 사용량 미확인은 일반 재시도 안내에 숨기지 않고 명시한다. UNKNOWN 호출을 자동 재실행하지 않는다.
- `pilot/scripts/deployment_readiness.py`는 CREATED/QUEUED/RUNNING 분석을 읽기 전용으로 검사한다. 실행 중 분석이 있으면 배포 사전 확인이 실패한다. 로컬 `deploy/active_run_guard.py`를 최근 두 배포 도구의 업로드 직전 경로에 연결했다. 이는 실행 중인 분석을 취소하거나 전체 수명을 API 종료 유예시간에 맡기는 방식이 아니다.

## 검증 및 운영 상태

- 워커 소실·단계 복구·병렬 검색 보존·UNKNOWN 차단·배포 사전 확인과 실행/AX/ARIZ JSON 회귀: 90 passed.
- 기존 AX, ARIZ 라우팅·필수 단계, 전 원안 검토 회귀: 118 passed.
- 새 유료 LLM 호출, 프로젝트 자동 재개, 미확인 사용량의 임의 정산은 수행하지 않았다.

현재 프로젝트는 이전 버전에서 이미 중단된 상태다. 신규 저장 로직만 배포한다고 과거 H 응답이 복원되거나 분석이 자동 완료되는 것은 아니다. 저장된 완료 응답은 재사용할 수 있으나, H 호출은 실제 사용량 확인 및 별도 재실행 판단이 필요하다. 과거 결과나 비용 기록을 삭제하여 이 제한을 우회하지 않는다.

이 문서 작성 시점에는 수정 소스와 회귀 검증을 완료했으며 운영 배포는 수행하지 않았다. 배포 시 현재 실행 중인 프로젝트가 없는지 사전 확인을 통과해야 한다.

## 추가 진단: 반복 재개 시 먼저 발생하는 비용

Q 지원/추가 탐색 패치 도중 사용자가 이 프로젝트의 추가 디버깅을 요청하여 운영
상태와 journal을 읽기 전용으로 재확인했다. 운영 데이터 변경과 재개는 수행하지 않았다.
현재 6개 트랙 A/B/C/E/F/G는 저장되어 있으나, H는 UNKNOWN 1건 때문에 계속 막힌다.
35건의 COMPLETED task가 있고 확정 비용은 $0.188722, 미확인 예약은 $0.133379다.
39/42/44번째 H 단계가 FAILED이며, 그 사이 근거 검색 계획/검색 단계가 기록돼 있다.
따라서 최초 컨테이너 교체 이후 재시도에서도 동일 미확인 호출을 만나 다시 멈춘 상태다.

기존 gateway는 해당 H 호출에 도착했을 때만 UNKNOWN을 차단했다. S5는 그 전에
다른 트랙/검색 작업을 시작할 수 있었다. 재현 테스트에서 UNKNOWN 예약이 있어도
`execute_stage()`가 stage handler를 호출하는 것을 확인했다. 수정 후에는 AX stage
진입 전에 journal의 UNKNOWN을 확인하고 정확한 UsageUncertain 사유로 중단한다.
확정 비용 표시를 맞추고 예약액·완료 트랙을 유지하며, 검색을 포함한 후속 stage
작업은 시작하지 않는다. 과거 pinned run에도 동일한 과금 안전 규칙을 적용한다.

테스트: `test_unknown_h_blocks_stage_before_retrieval_or_other_paid_work`.
수정 전 handler 호출 assertion 실패를 확인했다. 이 수정은 UNKNOWN을 정산하거나
H 결과를 생성하지 않는다. 공급자 사용량/응답의 실제 확인이 필요한 상태는 유지된다.

추가 사전 차단 테스트는 수정 후 통과했다. 이번 AX/Q 패치와 함께 수행한
627개 포괄 회귀에도 복구 테스트 7개가 포함되어 모두 통과했다. 운영에는 배포하지 않았다.
