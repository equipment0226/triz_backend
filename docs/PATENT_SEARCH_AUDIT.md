# 특허 검색 장애 점검 및 개선

## 실제 실행 이력 점검

2026-09-08 요청자 계정의 완료된 샘플 분석에서 검색 계획, 검색 캐시, 후보 목록과 적용성 검토 입력을 대조했다. 다음 6건은 검색어 74개에서 특허 후보가 모두 0건이었다. 논문 후보는 수집돼 후속 적용성 검토가 실행됐다.

| 분석 분야 | 특허 검색어 | 수집된 특허 후보 |
|---|---:|---:|
| 세포배양 산소공급·전단응력 | 12 | 0 |
| 연료전지 막 두께 | 9 | 0 |
| 진공 웨이퍼 이송 | 14 | 0 |
| 유기물 증착 균일성 | 11 | 0 |
| 3D 적층칩 방열 | 13 | 0 |
| 액침식 냉각 누수 | 15 | 0 |

EUV 사례는 초기 특허 검색에서 13건을 확보했지만 후속 특허 검색 결과는 모두 0건이었다. 최초 가상 컨베이어 사례에는 이전에 수집한 특허 48건이 남아 있었다.

운영 서버에서 최초 성공 검색어와 새 검색어를 재확인했을 때 Google Patents 검색과 원문 페이지 모두 HTTP 503과 `Sorry...` HTML을 반환했다. 서비스 요청 제한 또는 자동 접근 차단으로 판단되나 정확한 차단 조건은 응답만으로 확정할 수 없다. 과거 개별 요청의 HTTP 상태는 기록하지 않았으므로 과거의 모든 0건을 503이라고 소급 확정하지 않는다.

## 변경

- 현재 Google Patents 공개 검색 및 기존 제공자 선택 규칙·API 키·환경변수를 유지한다. 신규 검색 서비스와 키는 등록하지 않는다.
- 오류를 정상적인 0건으로 캐시하지 않는다. 검색 상태를 OK/EMPTY/PARTIAL/UNAVAILABLE/UNKNOWN으로 구분하고 HTTP 상태·조회 시각·재시도 가능 시각을 추론 이력에 남긴다.
- 기존 구분 없는 빈 특허 검색 캐시는 UNKNOWN으로 취급하고, 이후 검색 실행에서 원래 검색어로 재조회할 수 있도록 한다. 쿼리 수 제한에 도달했어도 실패한 기존 검색어는 재시도할 수 있다. 정상적인 0건은 계속 캐시한다.
- 같은 워커의 동시 실행에 대해 Google 요청 간격을 최소 1초로 제한한다. 차단·503·429·네트워크 오류 뒤에는 최소 5분간 반복 요청을 중단한다. 프록시·CAPTCHA 우회·다른 제공자 자동 전환은 하지 않는다.
- 이전에 확보한 자료는 재조회 장애로 지우지 않는다. 특허·논문 후보를 균형 있게 선택하고, 모델에 실제 전달된 후보 번호만 매칭 결과로 채택한다.
- 분석 현황과 보고서 한계 항목에 검색 상태를 표시한다. 해결책 카드의 근거 미확보 안내 문구는 다시 추가하지 않는다.

## 검증과 한계

백엔드 회귀는 503, HTTP 200 차단 페이지, 정상 0건, 잘못된 응답, 기존 빈 캐시, 쿼리 한도 상태의 재시도, 수집 복구, 제공자 선택 유지 및 특허 후보 누락을 검증한다.

Google 서비스 제한 자체를 해제한 변경은 아니다. 제한이 지속되면 실제 특허 후보 수집은 중단되며 오류 상태가 표시된다. 제공자/API 변경은 사용자가 추후 결정한다. 기존 분석 전체의 유료 모델 재실행은 수행하지 않는다.
