# 파이프라인 품질 리뷰 반영 내역

기준 리뷰: [PIPELINE_QUALITY_REVIEW.md](PIPELINE_QUALITY_REVIEW.md). 적용 대상은 현재 실행 소스인 `pilot/`이다.

## 문제 유형과 인과 분석

- 산업과 독립된 `problem_type`, 난이도, 혼합 문제의 `physical_scope`를 S0/S1의 기존 호출에서 추출한다. 산업 키워드는 배경 정보이며, 조직 문제의 분석 계약을 공학으로 변경하지 않는다.
- `domain.sync_contract()`가 프롬프트, 트랙, 검색, 평가 역할에 같은 유형을 제공한다. 명시적으로 선택한 난이도는 유지한다.
- 조직 문제는 행위자·정보·권한·유인·규칙, 정보 문제는 데이터·상태 전이로 분석한다. C/H는 물리 문제 또는 명시된 물리 하위범위에만 적용한다. 비기술 FULL/DEEP는 FOS를 사용한다.
- S1~S6, ARIZ, 검색, 평가의 공학 전용 강제 문구를 유형별 지시로 수정했다. 물리적 모순이 성립하지 않는 경우 이유를 기록하고 빈 배열을 허용한다.
- CECA는 노드 ID·중복·참조·순환·손실과의 연결성을 검사하고 모든 부모 경로를 고려해 깊이를 계산한다. 관측/가설, 가설 ID, 근거, 반증 방법을 저장한다.
- 관행을 절대 금기로 승격하지 않는다. 내재 제약은 미확인 soft 제약으로 저장하고, 금기는 확인된 사용자/규제 HARD 제약 ID가 있어야 강제한다.

## 근거 전달과 확정 경계

- 원문·첨부 사실·누적 사용자 답변·확정 경계를 묶은 사실 패킷과 관련 CECA 경로를 검증에 제공한다.
- 기술적 모순의 개선/악화 내용, 파라미터 정의, 결합 원인과 물리적 모순의 양쪽 요구 이유를 보존한다.
- 후보의 개입 변수, 메커니즘, 조건, 자기 반박, 이식 주의점, 반증 방법, 출처 ID를 S5→S6에 전달한다. 병합은 모든 원본의 조건과 출처를 유지하며 허위·중복 출처는 제외한다.
- 단순 앞부분 자르기 대신 모순·메커니즘/트랙별로 대표 후보를 순환 선택한다.
- S2의 선택을 canonical target 함수로 읽으며 상위 시스템·작용 범위·시간을 반영한다. S1은 과거 응답을 보존하고 현재 미응답 질문에만 새 답변을 연결한다.

## 후보 선택과 검증

- S5는 `RESOLVED`, `TRADEOFF`, `UNSUPPORTED`와 양쪽 요구의 성립 경로를 기록한다. `RESOLVED`는 조건부 설계 논리가 있다는 뜻이며 실증 완료를 의미하지 않는다.
- 수량·신규성 비율을 채우기 위해 약한 안을 유지하지 않는다. 핵심 모순 미해결과 단일 가설 의존성을 기록한다. ARIZ의 절충 판정은 통합 및 S6 후보 선택에 반영한다.
- B의 재정의 신호는 기존 통합 호출에서 검토한다. 선행 문제 정의를 몰래 바꾸거나 무한 재정의 루프를 실행하지 않는다. 미사용 `ariz.max_reformulation_loops` 설정은 제거했다.
- S6는 배정된 원시 아이디어만 구체화한다. 기본 12개를 5/5/2개로 생성하며, RAG가 있으면 영향 한도에 맞춰 3/5/4개로 배정한다. 성립하지 않는 안을 억지로 생성하지 않는다.
- 첫 배치 전용 심사를 전체 개념에 대한 독립 심사 1회로 바꿨다. 후보마다 PASS/REVISE/REJECT/UNVERIFIED와 사유를 보존한다. 검증 출력 상한은 후보 수에 맞춰 조정한다.
- 치명적 결함은 배제한다. 검증 누락·실패를 PASS로 바꾸지 않는다. 구조적 근거·검증 계획·자원 명시가 부족하면 보완 상태를 남긴다.
- 일반 독립 검증에는 해당 문제의 사실·파라미터 정의·도출 맥락을 제공한다. 수리 후에도 치명적 결함이 남으면 후속 분석을 중단한다. 검증 맥락 변경은 캐시를 무효화한다.
- S7 접미사 노드에도 생성 가설 격리를 적용했다. 보고서에는 모순 해소 근거와 설계 검토 상태를 표시한다.

## 평가와 검색

- GOAL(목표 달성), RESOLUTION(모순 해소), CAUSAL(인과 근거)을 기존 평가 호출에 포함한다. 조직 문제에서는 ADOPTION 비중을 높인다.
- 필수 평가 관점을 먼저 확보한 뒤 평가자 수 상한을 적용한다. 조직 문제의 회사 산업 때문에 엔지니어 역할이 먼저 선택되는 것을 방지한다.
- 같은 근거 수준이면 같은 점수를 허용하며, 누락 개념·잘못된 점수·근거 누락을 검사한다. 안전 veto는 0 가중치와 독립적으로 순위 집계에 반영한다.
- 평가자의 개선 제안은 순위·로드맵 입력으로 전달해 선행 검증/보완 과제에 반영한다. 별도 무제한 설계 수정 호출은 추가하지 않았다.
- 사전 검색은 트랙 출력에 의존하지 않고 경쟁 원인과 성립 조건을 판별할 자료를 찾는다. S6에는 배정 후보에 관련된 자료를 우선 전달한다.
- 상세 근거 적용성 검토를 평가 전에 실행한다. 조직 문제는 PAPER 기반 연구·운영 사례를 우선하며 PATENT를 강제하지 않는다.
- 효과 카탈로그는 요구 기능과 관련된 항목을 선택하고 원리·조건을 제공한다. 로컬 카탈로그의 지원 범위를 표시하며 새 표준해·과학적 사실을 생성해서 채우지 않는다.

## 피드백 재사용

- S10에 제목뿐 아니라 실제 메커니즘·조건을 제공하고 정제한 성공 패턴, 실패 패턴, 도메인 교훈을 상태와 RAG에 저장한다.
- 완료 후 API 피드백도 추가 모델 호출 없이 제공된 메커니즘·코멘트·누락 관점을 구조화해 저장한다.
- 높은 별점과 채택은 사용자 선호로 표시한다. 실증된 효과로 취급하지 않는다.
- 문제 유형의 호환성으로 검색을 제한하고 적용 조건 유사도를 반영한다. 같은 유형 내 타산업 사례는 별도로 표시한다.
- S1/S3에 실패 교훈을 전달하되 절대 제약으로 바꾸지 않는다. S6의 성공 사례 노출은 코드의 후보 배정으로 제한하고 사용한 사례 ID를 보존한다.

## 실행 시간·재개 호환성

- S4의 IFR/모순/트리밍을 병렬 실행한 뒤 핵심 문제를 선정한다. S7 배치는 병렬 실행하고 결과 순서는 유지한다.
- S5 검색과 트랙을 겹쳐 실행하되 해결 번들은 분리하고 완료 후 병합한다. 모든 모델 호출은 공유 semaphore와 비용 예약을 사용하므로 설정한 worker 상한을 넘지 않는다.
- S6는 후보를 사전 배정한 독립 배치를 병렬 실행한다. 검증은 전체 생성이 완료된 뒤 한 번 수행한다.
- `solve.max_escalations=0`이 기본이다. 추가 추론이 필요하면 1로 설정할 수 있지만 시간 증가 가능성이 있다. 추가할 트랙이 없으면 빈 재실행을 하지 않는다.
- `run.max_wallclock_min`은 사용자 입력 대기를 제외한 활성 실행 시간 예산으로 적용한다. 진행 중인 외부 요청을 강제 종료하는 제한이 아니라 **새 호출 전 검사**다. 단일 요청·검색의 timeout만큼 초과할 수 있다. 이어서 실행하면 새 시간 예산을 부여한다.
- 단계별 활성 시간과 실제 모델 요청 수·토큰·비용을 기록한다. 미사용 카테고리 수·강제 단계·신규성 비율 설정을 제거하고 `verification.skip_nodes`는 실행에 연결했다.
- 파이프라인 버전은 3이다. 이전 버전에서 근거 검토를 기다리던 실행은 새 근거 단계로 이동한 뒤 평가한다. 완료된 보고서는 되감지 않는다. 기존에 평가로 이미 잘린 후보는 과거 상태에서 자동 복원하지 않는다.

## 검증과 품질 비교

회귀 테스트는 `pilot/tests/test_pipeline_quality.py`에 추가했다. 유형 보존, 혼합 문제 범위, 질문 이력, 경계 선택, CECA 그래프, 근거 패킷, 출처 병합, 전체 개념 검증, RAG 한도, 검색 유형, 평가 관점, 병렬 실행, 이전 단계 마이그레이션, 상태 직렬화와 오프라인 비교 도구를 다룬다.

검증 결과: 전체 백엔드 테스트 **135개 통과**. 외부 LLM 호출 없이 검증했다. Python 구문, 평가 문제군 JSON 및 문서 링크도 확인했다. Qdrant 로컬 모드의 기존 검색 파라미터 경고 1건이 있으며 테스트 실패는 없다.

```powershell
.venv/Scripts/python.exe -m pytest pilot/tests -q
```

비교 문제군 12개는 `pilot/evals/pipeline_quality_cases.json`에 있다. 같은 문제·사용자 응답·후보 선택 순서로 생성한 변경 전후 `state.json`을 별도 디렉터리에 보관한 뒤 다음을 실행한다.

```powershell
.venv/Scripts/python.exe pilot/scripts/quality_eval.py --baseline BEFORE_DIR --candidate AFTER_DIR --output RESULT_DIR
```

도구는 외부 모델을 호출하지 않는다. `blind_review.md`, 검토자에게 제공하지 않을 `mapping.json`, 구조적 지표·비용·토큰·요청 수의 `metrics.csv`, 활성 시간 p50/p95의 `summary.json`을 만든다. 선택 후보의 실제 경계 의미가 동일한지는 검토자가 확인해야 한다. 과거 기록에 시간 정보가 없으면 값을 추정하지 않는다. 적은 표본의 p95와 필드 존재 개수는 품질 향상 증거가 아니다.

이번 반영은 모델·가격·외부 지식 카탈로그를 교체하지 않는다. 실제 모델 결과의 품질 향상률과 운영 지연 변화는 변경 전후 실험으로 확인해야 한다.
