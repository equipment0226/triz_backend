## BigQuery 특허 연결 — 실제 조회 검증 완료

- BigQuery 공개 특허 데이터를 직접 읽는 선택형 공급자를 구현했다. 한 단계의 검색어를 한 작업으로 묶고, 실제 제목·초록·공개번호를 기존 적용성 검토에 전달한다. Google Patents 웹페이지 재조회는 필요하지 않다.
- 무료 dry run, 작업당 최대 256 GiB, 이 배포의 월별 최대 768 GiB 예약·정산, 24시간 결과 캐시를 적용했다. 실제 공개 테이블 처리량이 상한을 넘으면 조회를 실행하지 않는다. 무료 잔여량을 보장하는 설정은 아니다.
- 인증·할당량·처리량 제한을 검색 결과 0건과 구분한다. 분석 현황·보고서에서 이유를 표시하며 해결책 카드에 근거 미확보 설명을 추가하지 않는다.
- BigQuery 최초 연결 코드의 백엔드 회귀 검사 66개·브라우저 검사 6개 통과, 프런트 프로덕션 빌드 통과.
- backend `b70fe7b`, frontend `e520d1f`의 GitHub 푸시와 Railway 배포 SUCCESS를 확인했다. 운영 서버에서 BigQuery SDK 3.45.0 로딩과 상한 설정, 공개 페이지 정상·실행 API 로그인 필요·공개 사례 9건을 확인했다.
- 사용자가 새 프로젝트 `project-fb0bcce1-74c5-472d-a91`의 서비스 계정을 Railway에 등록했다. 운영 컨테이너에서 인증·테이블 메타데이터 읽기·dry run·실제 쿼리를 통과했다. 키 값은 출력하거나 저장소에 포함하지 않았다.
- 공개 테이블 행 수 170,418,479개, 테이블 메타데이터의 마지막 수정 시각은 2026-04-26T20:32:15Z다. 최신 특허를 실시간으로 반영한다는 의미는 아니다.
- `gasket spring preload`, `stacked chip thermal cooling`, `substrate conveyor vibration isolation`을 한 작업으로 조회해 각각 6건, 총 18건의 특허 후보를 확보했다. 번호·제목·초록 기반 수집 확인이며, 18건 모두 해결안 근거로 검증된 것은 아니다.
- 검증 작업 ID: `triz_patents_cb1c12ced91d4b2b9e1240b0d6962148`. 예상 230,446,970,243바이트, 실제 청구 대상 처리량 230,447,644,672바이트(약 214.62 GiB). 청구 대상 처리량은 실제 결제액과 다르다. 월 상한과 무료 사용량을 고려하면 이 방식의 반복 검색 횟수는 제한적이다.
- 운영 변수 `PATENT_SEARCH_PROVIDER=bigquery`를 설정했다. 전환 배포 후에는 새 특허 검색에 BigQuery를 사용하며, 논문 공급자와 기존 저장 보고서는 유지한다.
- 실제 결과에서 확인한 미국 공개특허 번호의 DOCDB 앞자리 0 생략을 USPTO 형식에 맞게 보정했다. 데이터 원본 번호도 보존한다. 디자인·재발행·대만 특허의 문자 접두사를 지원하고 기존 캐시 링크도 추가 쿼리 없이 보정한다. 보완 후 백엔드 회귀 검사 74개가 통과했다.
- 등록 위치와 검증 명령: [BigQuery 연결 가이드](BIGQUERY_PATENT_SEARCH.md).

## 운영 구성

| 서비스 | 구성 |
|---|---|
| triz_front | Node 24 + React/Vite 빌드 + 인증된 API 프록시, 공개 HTTPS |
| triz_backend | Python 3.11 + FastAPI + 내장 MCP 52개 도구, private network |
| triz_backend-volume | `/data`, 첨부와 전체 상태·호출·단계·보고서 파일 |
| MySQL | 기존 MySQL 9.4 서비스, TRIZ 업무 데이터 |

| Postgres / Redis | 기존 n8n 내부 데이터와 큐 |

Primary·Worker의 기존 DB 연결과 encryption key는 유지했다. 사용자가 승인한 LLM 키와
별도의 신규 서비스 토큰·gateway 토큰을 Railway 환경변수에 설정했다.
실제 키와 데모 접속 비밀번호는 GitHub에 포함하지 않았다.

## 확인한 동작

- 인증 없는 `/api` 접근 차단, 인증 후 화면·이력·API 정상 응답.
- 실제 Edge 브라우저에서 홈페이지 → Sample Case → 분석 workspace 표시. JavaScript 오류 없음.
- 가상 제조 사례 1건과 텍스트 첨부 전송 → n8n worker → MCP → 실제 DeepSeek 호출.
- 사전 심층 질문에서 WAITING_HUMAN 정지 → 답변 전송 → 후속 분석 단계 진행.
- 실제 MySQL의 단계·모델 호출 저장, `/data/storage`의 첨부·상태·단계·호출 파일 보존 확인.
- 재배포 후 같은 MySQL 기록과 영구 파일 접근 확인.
- Jinja 보고서 템플릿을 운영 컨테이너에서 컴파일 확인.
- FEEDBACK 대기 중 동일 단계 요청 2회 재전송 시 추가 LLM 호출 없음. 이전 epoch 요청 거부 확인.

가상 사례는 배포 동작 검증용이다. 현업 실측 데이터나 답변 정확도의 검증 사례로 취급하지 않는다.
실제 모델 결과로 해결안 10개, 도식 29개, 전문가 6명의 평가를 포함한 보고서를 생성했다.
HTML 다운로드(약 106 KB)와 ZIP 31개 파일의 무결성을 확인했다. 해결안 10개 모두 근거 미확보 항목이
있어 표시되며, 이를 검증된 특허 기반 해결 사례로 취급하지 않는다. 현재 테스트는 보고서 생성 후
FEEDBACK 대기 상태로 보관한다. 품질 평가를 가장한 피드백을 RAG에 입력하지 않았다.

해당 1건의 기록: 단계 39개, 모델 호출 기록 49개, 입력 401,315 / 출력 107,109 토큰.
설정 단가 기반 누적 비용 추정은 약 $0.236이다. 연결 수정·재시도와 검증 과정을 포함한 단일
가상 사례의 기록이므로 정상 운영 평균이나 청구서 금액으로 일반화하지 않는다.

## 배포 과정에서 수정한 문제

1. 분리된 백엔드 이미지에 보고서 템플릿이 포함되도록 export 허용 목록 보완.
2. Railway 내부 IPv4 연결과 localhost MCP 연결을 위해 IPv4/IPv6 이중 리스너 적용.
3. 내장 MCP의 동기 분석이 API event loop를 막지 않도록 장시간 도구를 별도 스레드에서 실행.

로컬 백엔드 회귀 30개, 스모크 8개, 기존 UI 회귀 5개 통과. 운영 gateway HTTP 테스트와
MCP lifespan/프로토콜·IPv4/IPv6 접속 검사 통과. 실제 API·브라우저 점검은 fixture UI 회귀와 별도로 수행했다.

## 운영 방법

### 특허 검색 오류 처리 개선 (2026-09-08)

Google Patents 검색·원문 요청의 HTTP 503을 실제 운영 서버에서 확인했다. 기존 빈 결과 캐시와 매칭 전 특허 후보 누락을 수정하고, 검색 장애 진단·요청 간격·재시도 대기·보고서 및 분석 현황 표시를 추가했다. 현재 검색 제공자/API 키 설정은 유지한다. 원인과 범위는 [특허 검색 점검 기록](PATENT_SEARCH_AUDIT.md)을 참고한다.

### 제약 검토 재개 오류 수정 (2026-09-08)

- 다수 해결책 × 제약 전체를 한 번에 출력하다 출력 한도가 초과됐고, 기본 보류 판정에 대한 사용자 결정을 제출한 뒤에도 이전 실패 단계가 진행을 차단했다.
- 제약 검토는 최대 2개 개념, 목표 24개 개념·제약 쌍을 기준으로 나눈다. 각 호출에는 해당 개념의 제약 전문을 유지한다.
- 모든 보류 후보의 유지·제외 선택을 서버에서 검증하고, 불완전한 제출은 대기 질문을 보존하며 400으로 거절한다.
- 사용자 결정 및 현재 분석과의 일치 여부를 저장한다. 재시도는 적용된 결정을 재사용한다. 해당 자동 검토 실패 기록은 보존하면서 사용자 결정으로 처리한 실패만 진행 차단에서 제외한다.
- 조건부 유지의 판정은 CONDITIONAL로 유지하며, 다른 새 분석 호출이 실패하면 계속 중단한다. 제약 검토 이전부터 재분석하면 저장된 결정을 무효화한다.
- 백엔드 회귀 47개 통과. 자동 검토 실패→보류→유지·제외 제출→다직군 평가 진행을 재현해 확인했다.

### 보고서·화면 추가 개선 (2026-09-08)

- 보고서 문장을 평문으로 통일하고, 저장된 분석도 현재 템플릿으로 재구성한다. 원본 분석 데이터는 변경하지 않는다.
- 내용 길이 기준 표 열 비율, 제약 판정표 8개 열 단위 분할, 시스템 제약의 이유·오답 글머리 제거.
- 도식을 기능·자원·인과사슬·IFR·개별 모순·해결기법·개별 해결안 위치에 삽입한다. 중복 9 Windows 도식은 제외한다.
- 모든 SVG 연결은 상자 사이 빈 공간을 따라 우회한다. 역방향·자기 연결도 꺾은선으로 표현한다.
- 작업 화면은 분석 현황/해결안/보고서/피드백으로 구분한다. 보고서에 해결안 카드와 피드백 양식을 반복하지 않는다.
- Sample Case에도 같은 보고서를 적용하고, 분석 도식 탭과 보고서 다운로드 버튼을 제거한다. 공개 동의 및 계정별 작업 권한은 유지한다.
- 실제 참고자료가 없는 해결책 카드는 근거 미확보 안내를 표시하지 않는다. 연결 근거·유사 사례 모두 제목 링크와 작은 설명을 동일하게 표시한다.
- 평가 순위의 기본값 99는 화면·보고서에서 ‘추가 도출’로 표시한다. 초록색 로봇 SVG 파비콘 적용.
- 로컬 백엔드 40개, UI 6개, gateway 1개 검증. 기존 실제 보고서 도식 28개·표 59개를 검사했다. 글자 잘림 및 상자 관통 화살표 0건.
- 새 프런트는 이전 보고서 응답도 지원한다. 프런트 배포 완료 후 백엔드를 배포한다.

1. 원본 수정 후 `python deploy/export_repositories.py`로 `release/`의 두 저장소 사본을 갱신한다.
2. 해당 저장소에서 diff 확인 → commit → `git push origin main`.
3. Railway에서 해당 서비스의 배포가 SUCCESS인지 확인한다.
4. 사이트 로그인 후 이력·문제 분석·다운로드를 확인한다. DB와 `/data` 볼륨을 삭제하지 않는다.

공유 데모 로그인은 제거했다. 공개 페이지는 누구나 접속하고, Problem Solving은 Google 계정으로 가입·로그인한다.
본인 계정으로 설정한 n8n 관리자 비밀번호는 이 파일과 별개다.

전체 산업별 품질 평가, S3 확장, 부하·장애 복구 훈련은 후속 범위다.

## 추가 개선 — Google 로그인·전체 보고서·무료 특허 검색

- Main 명칭 변경, 특정 기업 활용 사례 영역 삭제, About us 프로필 추가.
- Main / Tool 소개 / About us 공개. Sample Case는 무료 베타 동안 모든 회원의 실제 분석 사례·도식·보고서를 비회원에게도 공개한다. Problem Solving에서 분석 실행·수정은 Google 로그인 필요.
- 웹 OAuth authorization code + PKCE/state/nonce, 공식 Google 라이브러리 ID 토큰 검증. 최초 로그인 시 회원 자동 생성.
- MySQL 계정·12시간 세션, HTTP-only Secure 쿠키, 로그아웃 시 세션 철회. gateway는 클라이언트가 보낸 인증 헤더를 제거한다.
- 작업용 API의 실행 ID 경로를 소유자로 제한. 공개 사례 전용 GET API(`/api/public/runs`, `/{id}/view`, `/{id}/report`)는 로그인 없이 읽기만 허용하며 계정·세션 필드는 반환하지 않는다. 개인 피드백 RAG도 계정별로 제한.
- 신규 분석은 필수 공개 동의 체크를 받아 제출하며 서버에서도 동의를 검사한다. 공개 동의 시각·주체는 published_runs에 기록한다. 목록과 상세·보고서는 이 공개 기록이 있는 사례만 반환한다. 기존 사례는 요청자 소유 확인 후 요청자 승인에 따라 개별 등록한다.
- 기존 local 실행의 관리 소유권은 LEGACY_OWNER_EMAIL과 일치하는 Google 인증 계정으로만 첫 로그인 시 연결한다. 공개 동의된 사례의 열람에는 이 소유권 제한을 적용하지 않는다.
- 원 PoC report_full 템플릿의 문제 정의·제약·시스템/기능·자원·원인·모순/IFR·해결기법·아이디어·해결안·평가·로드맵을 보고서 탭과 단일 HTML에 함께 제공.
- 기존 저장 보고서도 다운로드 시 현재 템플릿으로 렌더링. ZIP 버튼 제거. 도식과 텍스트를 포함한 HTML 하나를 내려받으며 브라우저에서 PDF 인쇄 가능.
- 한글 폭과 전체 줄 수로 SVG 노드 크기를 계산. 긴 라벨을 자르지 않으며 관계 설명은 번호와 전체 범례로 표시. 브라우저 도식 확대·스크롤 제공.
