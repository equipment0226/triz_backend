# 보안 점검과 첨부파일 처리

2026-09-30 서버와 Agentic workflow를 코드로 점검하고, 운영에서는 인증 없는 조회가 차단되는지만 확인했다. 공격용 파일 전송, 부하 시험, 실제 프로젝트 변경, 유료 모델 호출은 하지 않았다. 베타 서비스의 공개 동의와 샘플 프로젝트 공개는 의도한 기능이므로 그대로 유지했다.

## 확인하고 보완한 부분

| 문제 | 적용한 보완 | 기존 자료 보호 |
|---|---|---|
| 첨부 추출이 실패하거나 여러 첨부 중 뒤의 파일이 거부되면, 먼저 저장한 파일이 남았다. 반복 요청으로 저장 공간을 소모할 수 있었다. | 새 요청에서 만든 파일을 추적하고 실패 시 정리한다. | 프로젝트에 연결된 파일은 남긴다. 저장 여부를 확인할 수 없거나 생성 중 요청이 취소되면 지우지 않는다. |
| PDF·XLSX 파싱이 API 프로세스에서 실행되고, 전체 실행 시간과 메모리 제한이 없었다. | 고정된 별도 Python worker에서 추출하고 시간·메모리·동시 실행 수를 제한한다. XLSX 압축 해제 크기와 PDF OCR 픽셀 수도 먼저 검사한다. | 정상 파일의 추출 형식과 원본을 보존한다. 기존 첨부를 다시 처리하거나 수정하지 않는다. |

실패한 과거 파일을 일괄 삭제하는 작업은 포함하지 않는다. API 요청, 분석 상태, 피드백, 학습 결과의 기존 저장 형식도 바꾸지 않는다.

## 처리 흐름과 기본 한도

```mermaid
flowchart LR
  A[인증된 새 첨부 요청] --> B[파일 수·형식·크기 검사]
  B --> C[요청별 새 파일 저장]
  C --> D[동시 실행 제한]
  D --> E[고정 worker: 파싱·OCR]
  E --> F[추출 결과 검사]
  F --> G[프로젝트와 첨부 연결]
  C -->|실패| H[이번 요청의 미연결 파일만 정리]
  E -->|실패·시간 초과| H
  G -->|기록 확인| I[연결된 원본 유지]
```

| 항목 | 기본값·동작 |
|---|---|
| worker 추출 시간 | `DOCUMENT_PARSE_TIMEOUT_SECONDS=660`, 설정 범위 1–3600초. 기존 30페이지 × 페이지별 OCR 20초를 수용한다. 실행 슬롯 대기에도 별도로 같은 시간 제한을 적용한다. |
| Linux worker 메모리 | `DOCUMENT_PARSE_MEMORY_MB=1536`, 설정 범위 64–4096MiB. 가상 주소 공간 한도이며 상속받은 더 낮은 한도를 올리지 않는다. |
| 동시 추출 worker | API 프로세스당 기본 2개. `DOCUMENT_PARSE_CONCURRENCY`로 1–4개를 설정한다. 여러 API 프로세스를 운영하면 각 프로세스에 적용된다. |
| XLSX 압축 내부 | 최대 2,048개 항목, 항목별 128MiB, 합계 256MiB. 암호화 항목은 거부한다. |
| PDF OCR | 기존 130dpi 유지. 페이지·MediaBox·CropBox를 확인해 2,500만 픽셀을 넘는 렌더링은 생략하고 미추출 사유를 남긴다. |
| 반환 데이터 | JSON 읽기 최대 2MiB, 본문·근거 항목의 기존 크기와 형식 검사. |

한도에 걸린 파일은 자동으로 재시도하지 않는다. 메모리 제한은 Linux 운영 환경에 적용되며 Windows에는 동일한 메모리 제한이 없다. 별도 worker는 시간·자원 격리를 위한 장치로, 파일 시스템과 네트워크까지 분리하는 보안 샌드박스는 아니다. 반환 JSON 검사 역시 임시 출력 파일의 물리 디스크 할당량을 제한하는 장치는 아니다.

## 확인 범위와 재검증

API 소유권 검사, 프론트 인증 헤더 처리, 세션·OAuth, 내부 MCP 호출 인증, 특허 자료 접근, HTML/SVG 정리, 외부 검색 결과의 사용 경로를 정적으로 검토했다. 점검한 경로에서는 추가로 확정할 수 있는 인증 우회나 외부 자료를 통한 임의 도구 실행을 찾지 못했다. 모든 취약점이 없다는 의미는 아니다.

운영에서 일반 API의 무인증 조회, 위조 인증 헤더를 넣은 조회, 내부 세션 조회를 각각 시도했고 모두 `401`을 반환했다. 응답 본문이나 프로젝트 내용을 공개 로그에 남기지 않았다.

회귀 검증은 정상 TXT·CSV·XLSX·PDF·이미지의 결과와 원본 보존, 비정상 파일 거부, worker 제한과 종료, 첨부 일괄 처리 실패, 중복 접수, 부분 저장 실패, 요청 취소 후 생성 완료를 포함한다. 테스트에서는 가짜 worker와 작은 파일을 사용하며 운영 자원을 소진시키지 않는다.

```powershell
.venv/Scripts/python.exe -m pytest pilot/tests/test_docparse_isolation.py pilot/tests/test_upload_security_cleanup.py pilot/tests/test_run_submission.py pilot/tests/test_accounts_and_search.py pilot/tests/test_patent_access.py pilot/tests/test_refactor.py -q
```
