# 과학효과 검색 흐름 점검 — 2026-09-16

## 현재 구현

현재 H_EFFECTS는 **로컬 카탈로그 전체에 대한 어휘 검색 → 상위 24개만 LLM 상세 검토**다. 산업 트리를 내려가며 가지를 배제하는 계층 검색은 아니다. 전체 항목을 대상으로 검색 점수를 계산하는 것과, 모든 항목을 모델에 넣어 해결안을 생성하는 것은 서로 다른 비용을 가진다.

| 단계 | 실제 구현 | 범위와 한계 |
|---|---|---|
| 요구 기능 | `nodes._required_functions` | IFR X요소와 유해·불충분 기능 중 앞의 최대 4개. 산업 용어 및 일반 표현이 남아 있다. |
| 전체 후보 검색 | `effect_catalog.select_effects` | 19개 기능군의 269개 효과를 평탄화하여 이름·별칭·원리·조건·응용 등의 어휘를 전역 채점한다. 한국어 2글자 조각도 사용한다. |
| 후보 축소 | `ax.runtime.effect_candidates`, `nodes._track_h` | `limit=6 × 4 = 24`개. 요구 기능별 최소 후보, 기구별 다양성, 다른 산업 후보의 할당량, 관련성 최저 점수가 없다. 현재 H 경로에 별도 임베딩 검색은 없다. |

공학 DLC는 도메인 선제 제한 없이 전체 효과를 검색한다. 조직/정보 문제는 의미가 다른 물리 효과의 강제 적용을 막기 위해 INFORMATIONAL 범위로 제한한다. 이는 산업별 검색 제한과 다르다. 별도 ARIZ Part 5를 실행하는 경우 효과 후보 상한은 40개이며, 이번 AX 기본 경로에는 ARIZ가 포함되지 않는다.

별도 특허·논문 검색도 있다. 검색어 설계 프롬프트는 산업명을 제거한 기능 대응 및 최소 한 개의 `cross_domain` 검색어를 요구한다. 벡터 특허 공급자는 전체 산업 컬렉션을 대상으로 근사 최근접 검색을 하고, 질의당 최대 72개를 회수하여 특허 패밀리 중복 제거 후 6개를 반환한다. 모든 특허를 매번 LLM으로 검토하는 방식은 아니다. `cross_domain`의 기능 대응 품질이나 최소 건수를 코드가 강제 검증하지는 않는다. 저장된 특허 전체와 세계의 모든 특허도 동일한 범위가 아니다.

AX 기본 조율은 A_MATRIX/B_SEPARATION/H_EFFECTS 세 경로다. 별도 G_FOS는 기본 경로에 포함되지 않는다. 외부 근거 검색 프롬프트에 산업 전이 지시가 있다고 해서 효과 후보군과 최종 해결안의 산업 전이가 보장되는 것은 아니다. 이번 DLC 시험에서는 비용·환경 격리를 위해 특허 벡터 검색을 껐으므로, 실제 운영 특허 컬렉션의 교차 산업 검색 품질은 그 시험으로 검증하지 않았다.

## DLC 기록에서 확인한 문제와 수정

[저장 입력 재현 기록](evals/DLC_EFFECT_SEARCH_AUDIT_20260916.json)은 모델 호출 없이 실제 전달된 24개 ID와 재계산한 ID가 일치함을 확인한다.

- 24개 중 PHYSICAL 13개, BIOLOGICAL 11개였다. 열전도·강제 대류와 함께 효소 촉매·광합성 등도 올라왔다. 분야가 다르다는 이유로 부적합을 단정할 수는 없지만, 해당 문제와의 기능·작동 조건 대응 없이 이 결과를 산업 전이 성과로 볼 수 없다.
- 질의의 “기능”, “수행” 같은 일반 표현이 “생물학적 작용을 이용해 기능을 수행한다”라는 그룹명과 일치하고 그룹명 가중치도 받는다. 유사한 표현이 점수를 높이는 경로가 있다. 단어 일치와 기구의 적합성을 구분해야 한다.
- 효과 블록은 11,031자였고 H 호출의 전체 입력/출력 사용량은 14,460/3,490 토큰이었다. 전체 입력에는 공통 지시 및 다른 맥락도 포함된다. 항목 수를 제한해도 토큰 예산을 고정한 것은 아니다.
- 모델이 ID를 `[7.1]`처럼 반환하여 기존의 정확 일치에서 탈락했다. 다섯 적용안 모두 카탈로그 연결이 null로 남아 있었다. 바깥 대괄호 한 쌍만 정규화하고 실제 카탈로그 ID와 정확히 대조하도록 수정했다. 저장된 원 응답을 재처리하면 `7.1, 7.2, 16.14, 7.2, 7.6`으로 연결된다. 과거 보고서·실행 스냅샷은 수정하지 않았다.
- 정본의 `limitations`도 적용안의 `catalog_limitations`로 명시 보존한다.
- 조직/정보 문제의 AX 필터가 `INFORMATION`을 사용해 실제 정본 `INFORMATIONAL`과 불일치하던 오류를 수정했다.

이 수정은 출처·조건 연결의 정확성을 보강한다. 검색 순위의 일반 단어 편향, 산업 전이 후보 확보, 실제 적용성 증명은 별개의 남은 과제다.

수정 후 카탈로그·AX·학습·공급자 중단 관련 회귀검사 53개가 통과했다. 검사는 모두 로컬 모의 호출이며 추가 유료 API는 사용하지 않았다. 새 검색 정책의 품질 검증이나 실장비 검증을 대신하지 않는다.

## 제안: 전역 검색을 유지하고 상세 검토를 단계적으로 제한

아래는 설계 제안이며 아직 검색 정책에 적용하지 않았다. 상한 24개와 분배 비율은 비교 시험의 출발점이지 최적값 또는 비용 보장값이 아니다.

1. **기능 표현을 먼저 정규화한다.** 기존 분석 호출 결과에 작용 주체·작용·대상, 입력/출력, 핵심 상충 변수, 확인된 필수 조건을 구조화한다. 원 질의와 함께 산업 용어를 줄인 일반화 질의를 보존한다. 일반 표현을 낮게 가중하고 핵심 기능을 앞의 4개 순서만으로 누락하지 않도록 우선순위를 명시한다.
2. **모든 산업을 검색 범위에 둔다.** 현재 규모에서는 269개 전체를 로컬 채점한다. 규모가 커지면 미리 계산한 효과 벡터와 어휘 인덱스를 병행할 수 있다. 임베딩 구축·갱신 및 검색 서버 비용은 별도로 기록한다. 산업 분류는 참고 속성과 설명에 사용하고, 산업이 다르다는 이유로 후보를 차단하지 않는다.
3. **다양한 경로를 한 후보 예산에 합친다.** 초기 비교안은 직접 기능 대응 12개, 산업 용어를 제거한 기능/기구 대응 8개, 기존 기구와 다른 탐색 후보 4개다. 기구 중복을 제거하고 출처 산업과 기능 대응을 기록한다. 채울 만한 후보가 없으면 무관한 후보로 수량을 채우지 않는다. 후보 출처 산업을 모르면 미확인으로 둔다.
4. **적용성 판정 후 소수만 생성한다.** 확인된 물리적 불가능 조건은 제외 이유를 남긴다. 조건이 미확인인 후보는 검증 의무와 함께 유지한다. 24개 이내 후보를 한정된 입력 토큰으로 비교한 뒤, 3~6개 기구를 상세화하는 안을 비교 시험한다. 현재 호출 수를 기준으로 불필요한 추가 LLM 왕복을 만들지 않도록 기존 H 호출에 비교를 통합한다.
5. **실패한 조건을 가지고 재검색한다.** 예를 들어 “유량 증가로 펌프 전력이 초과됨”을 다음 요구 기능으로 바꿔, 동일 유량에서 열전달/열저항을 개선하는 후보를 찾는다. 추가 라운드 수, 후보 수, 입력/출력 토큰, 대기시간 및 최종 검증 예약 예산을 제한한다. 조율 중 HITL 대기는 만들지 않는다.

기능→기구→적용 조건의 계층은 후보를 설명하고 정밀화하는 데 쓴다. 상위 기능 하나를 잘못 골라도 다른 경로를 찾을 수 있도록, 전역 검색 경로와 다중 기능 소속을 유지한다. 산업→하위 산업 순서로 검색 범위를 닫지 않는다.

DLC 일반화의 예는 “공급 온도를 높여도 열원 상한을 넘지 않게 열경로 저항을 낮춘다”, “피크 열부하와 평균 방열의 시간차를 흡수한다”, “추가 펌프 동력을 제한하며 분기 유량을 균등하게 한다”다. 이 기능에 맞는 기구를 다른 산업에서 찾고 현재 재료·압력·온도·열유속·안전 조건과 대조한다. 구체적 기구의 적합성과 성능은 아직 가설이다.

## RL의 역할과 검증 기준

현재 RL은 12개 작업 종류와 8개 상태 특성으로 작업 선택을 학습한다. 과학효과별 검색 순위, 12/8/4 비율, 검색 폭을 학습하는 모델은 아직 아니다. 이 제안을 연결하려면 검색 결정/특성/결과 로그와 정책 스키마 버전을 추가해야 한다.

학습 대상 후보는 “현재 후보를 상세 검토 / 다른 기능 표현으로 전역 재검색 / 작동 조건의 근거 수집 / 중단”이다. 카탈로그 항목의 과학적 진위를 RL이 결정하게 하지 않는다. 예산 절감만 보상하면 익숙한 산업에 고착될 수 있으므로, 독립 검토된 기능 대응·기구 다양성·후속 시험 결과와 비용을 함께 평가하고 전역 탐색 경로가 없어지지 않게 한다. 선택되지 않은 후보의 미관측 성과를 실패로 라벨링하지 않는다.

다음 비교는 추가 유료 호출 전에 로컬 검색부터 시작할 수 있다. 현재 269개에서는 전 항목을 검토하여 만든 사람 검토 기준 집합으로 후보 누락을 평가한다. 현재 어휘 상위 24개, 기능 일반화 검색, 전역 검색과 다양성 보존 조합에 동일 토큰 예산을 적용하고, 알려진 유효 기구 회수율·다른 산업의 유효 기구 수·기능별 누락·부적합 후보 비율을 비교한다. 이후 소수 후보의 적용 조건 검토 정확도와 실제 입력/출력 사용량을 비교한다. DLC 한 건의 성공만으로 일반화·RL 성능 개선을 주장하지 않는다.
