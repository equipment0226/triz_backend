# S8 직군별 독립 평가

각 검토자가 해결안을 독립적으로 받아 자신의 직무·KPI와 담당 평가 차원으로 점수를 매긴다. 타 직군에 질문하거나 답변을 받아 재평가하는 호출은 없다. 실행은 `meeting.evaluate`의 기본 `independent` 경로이며, 프롬프트는 `P_S8_REVIEW`다.

검토자 구성 시 `mandate`에 역할이 책임지는 KPI와 목표 방향을 명시한다. 제공되지 않은 수치 목표는 만들지 않는다. 평가에는 문제, 관측 사실, 제약, 성공 기준, 전체 해결안과 연결된 근거·검증 범위를 제공한다. 다른 직군의 평가·대화·참가자 목록과 TRIZ 생성 이력은 전달하지 않는다.

## 결과와 표시

하나의 응답에 담당 차원별 `scores`와 해결안별 `concept_comments`를 함께 받는다. 보고서용 최종 코멘트는 직군별 핵심 판단과 가장 중요한 실행 조건·우려를 담은 1~2문장이다. 권장 길이는 160자 이내이며, 누락·빈 코멘트·320자 초과 응답은 수리한다. 점수와 항목별 근거를 코멘트에 반복 나열하지 않는다.

보고서는 해결안마다 직군당 한 행의 최종 의견을 표시한다. 해결안 카드는 기존 항목별 점수와 중복 항목 제거를 유지한다. 실제 안전 veto는 낙관적인 최종 코멘트로 가리지 않는다. 상세 점수 집계와 순위 산정 기준은 그대로다.

## 호출과 중단 복구

```yaml
evaluation:
  mode: independent
  min_reviewers: 4
  max_reviewers: 6
  review_max_tokens: 8000
  review_batch_rows: 12
  review_repair_attempts: 2
```

직군별로 병렬 호출하며, 해결안 수 × 담당 차원 수가 12행을 넘으면 출력 대상 해결안을 나눈다. 각 호출은 전체 해결안의 비교 맥락을 유지한다. 12행 이내라면 검토자당 기본 1회로 점수와 최종 코멘트가 완결된다. 검토자 생성·순위 산정·수리·재시도·설정에 따른 독립 검증 호출은 별도다.

저장 호환성을 위해 기존 `evaluation.meeting` 필드를 사용한다. 독립 평가의 `rounds`는 0이고, `initial_reviews`, `questions`, `answers`, `communication_summary`는 비어 있다. `final_reviews`에 직군별 점수와 코멘트를 저장한다. 과거 대화 평가의 완료 결과를 새 독립 평가로 간주하지 않는다. 기존 완료 케이스는 조회만으로 재실행하거나 변경하지 않는다.

완료된 직군·분할 응답은 입력 해시와 함께 저장한다. 재시도 시 현재 검증을 통과하는 완료 응답은 재사용하고 미완료 부분만 호출한다. 점수 누락·중복·부적절한 값과 코멘트 누락을 검사하며, 실패를 기본 점수로 채우지 않는다. 모든 직군 평가가 완결된 뒤 집계·순위를 산정한다.

## 근거자료 적용성 검토의 출력 한도

`evidence.match_max_tokens`를 8,000으로 지정해 종전 T2 기본 4,000토큰으로 응답이 잘리던 문제를 보완했다. 검색 후보 전체는 유지하며, 프롬프트에서 해결안·자료 유형별 관련성 높은 대표 근거를 최대 2개씩 반환하도록 한다. 작동 원리 대응과 적용·실패 조건을 함께 남긴다. 잘린 JSON을 성공으로 처리하지 않는 정책과 실행 비용·시간 예산은 유지한다.

## 검증

`test_independent_reviews.py`는 독립 호출·KPI 격리, 전체 점수와 짧은 코멘트 저장, 보고서·카드 표시, 분할 실패 후 재개, 과거 대화 캐시와의 분리, 근거 후보 보존 및 8,000토큰 적용을 검증한다. 이전 회의 경로 테스트는 `evaluation.mode: discussion`을 명시한다.
