# 역질의 재개·중단 알림·모바일 화면 수정

2026-09-09 운영 기록을 읽어 원인을 확인했다. 점검을 위해 사용자 실행을 재개하거나 답변을 변경하지 않았다.

## 확인한 원인

- S1 추출 호출이 실패한 뒤 역질의가 생성됐고, 답변 후 동일 추출이 완료되어도 이전 FAILED 기록 때문에 단계가 다시 실패했다. 운영 기록에서 실패→질문 생성→답변 반영 완료 순서를 확인했다.
- 운영 S1 출력 상한은 2,000토큰이었다. 같은 입력이 출력 길이 초과로 3회 실패한 기록이 있었다. 별도 실행의 S5 통합에서도 출력 잘림이 있었다.
- 알림 조회는 WAITING_HUMAN만 포함해 FAILED/INTERRUPTED가 누락됐다. n8n 모드에서는 기존 프로세스 중단 감지도 비활성화돼 있었다.
- 모바일 알림은 backdrop-filter가 적용된 헤더 안에서 fixed로 렌더링됐고, 메뉴·본문의 여백과 태블릿 단계 메뉴 전환 기준이 달랐다.

## 변경

- 답변 제출 시점 이전 실패만, 이후 완료된 동일 단계·노드·역할·프롬프트·호출명으로 해소한다. 원래 실패 기록과 관계없는 실패는 유지한다.
- S1이 실패하면 이전 사실·제약과 제출 답변을 보존하고 재시도 상태로 전환한다. 빈 추출 결과로 새 역질의를 만들지 않는다. S0의 카탈로그 대체 경로는 사용자 확인을 별도 해소 근거로 기록하며 모델 검토 성공으로 표시하지 않는다.
- S1 출력 한도를 4,800으로 지정하고 중복 설명을 줄인다. S5는 원본 ID와 통합 판단만 출력하고 원본의 자원·조건·출처를 코드에서 복원한다. 잘린 JSON은 계속 실패로 취급하며 재요청 때 필수 대상 ID·수치·금지사항을 생략하지 않도록 한다.
- 로컬 워커 종료 중 재개 요청 유실과 n8n 타임아웃의 이전 상태 덮어쓰기를 방지한다.
- FAILED/INTERRUPTED도 소유자별 알림에 포함한다. 알림 ID는 같은 중단 동안 유지되고 새 재시도 후 발생한 중단에는 새 ID를 부여한다. 원시 오류·사용자 답변은 알림에 넣지 않는다.
- 실행 중 표시가 남았지만 실행 잠금을 얻을 수 있으면 중단으로 감지한다. 큐와 단계 사이의 전달 지연에는 180초 유예를 적용한다. 시작 시와 30초마다 확인하고, 알림 화면은 15초마다 조회한다. 정상 실행 잠금과 사용자 입력 대기는 보존한다. 분석을 자동 재개하지 않는다.
- 알림을 body 포털로 옮기고 모바일에서는 화면 중앙에 배치한다. 알림 목록과 팝업을 동시에 겹쳐 띄우지 않는다. 재시도 알림 버튼은 실행 상세를 열고 실제 재시도는 사용자가 선택한다.
- 메뉴와 본문 여백을 맞추고 모바일 분석 탭 5개를 화면 폭 안에 배치한다. 긴 보고서는 세로로 읽고 넓은 도표는 해당 영역에서 스크롤한다.

## 검증

- 배포용 저장소 기준 전체 백엔드 회귀 검사 161개 통과. 외부 모델 호출 없이 실패 후 역질의 재개, 실패한 답변 보존, 잠긴 워커 보호, 타임아웃·실행 회차 경쟁, 알림 소유자 분리·중복 억제, JSON 잘림 거부를 검증했다.
- Playwright 17개, 프런트 게이트웨이 검사 1개, 프로덕션 빌드 통과. 마지막 UI 보완 후 신규 브라우저 검사 3개를 재확인했다.
- 320~1366px 폭, 390×844 및 1366×768 화면에서 가로 넘침과 분석 탭 표시를 확인했다. 스크롤한 모바일 화면에서도 알림의 중앙 배치를 검사했다.

실제 모델 출력 길이와 지연의 개선율은 이번 회귀 검사로 측정하지 않았다. 기존에 중단된 분석은 저장된 상태에서 사용자가 이어서 실행할 수 있다.
