# Representative idea consolidation, maximum ten

The user replaced the unlimited consolidation policy with a hard limit of ten
representative ideas before detailed concept review. S5 still receives every
source, facts, contradiction and hard/soft constraint. Its agent compares working
mechanisms, interventions, applicability conditions, causal contribution and
verification feasibility. It merges equivalent designs and chooses at most ten
representatives. Distinct alternatives that cannot legitimately merge receive
individual deferral reasons, rather than being silently truncated or declared
technically impossible. There is no quota to fill ten slots.

The server validates exact, disjoint source coverage across selected groups and
deferred sources, merge reasons, deferral reasons, selection rationale, and the
hard output limit. Invalid output enters the existing repair loop; persistent
failure preserves source state. Earlier unlimited results are not accepted as
current consolidations. Deferred full source objects are reconsidered if the
problem changes and the representative inventory remains applicable.

S6 reviews every representative without an additional eight-candidate cap. The
existing technical audit and hard/soft constraint gates remain unchanged. The
report preserves all original ideas, source-to-representative mappings and
deferral reasons in a collapsed detail section. Frozen older reports retain their
prior policy and results. The cap governs consolidation; legacy projects already
past S6 are not automatically rewritten or restarted by deployment.

Validation covers complete 46-to-10 data flow, oversized response repair,
non-prefix representative selection, missing/duplicate/fabricated IDs, deferral
coverage, old pinned prompt compatibility, frozen AX report lineage, hard/soft
gates and downstream ranking. No paid model calls or project resets are used.
