# 모델 API 중단 복구 — 2026-09-10

운영 실행 이력을 조회했을 때 완료 43건, 중단 2건, 실패 1건이었다. 진행 중으로 남은 실행은 없었다. 중단·실패한 3건의 마지막 모델 호출은 모두 HTTP 402 `Insufficient Balance`였다. 각 실행의 내부 비용은 3달러 예산보다 낮았으므로, 분석 예산과 별개인 모델 공급자 계정 잔액 부족이 직접 원인이다.

기존 게이트웨이는 계정 잔액 오류도 JSON 형식 오류와 함께 재시도했다. 이후 실행기가 기본값을 반환하면서 다직군 평가는 이를 점수 배열 누락으로 해석했다. 다른 병렬 트랙과 후속 병합도 같은 계정으로 실패 요청을 보낼 수 있었다. HTTP 오류는 물리 요청 이력에서 누락되고 최대 시도 횟수로 집계되었다.

변경 사항:

- HTTP 401·402·403은 계정 설정이 필요한 오류로 분류하고 첫 실패에서 재시도를 중단한다. 429·서버 오류의 제한된 재시도와 잘린 JSON 거부는 유지한다.
- 병렬 호출이 공유하는 실행 컨텍스트에 오류 상태를 기록한다. 슬롯을 기다리던 요청과 후속 요청은 호출을 시작하지 않는다. 이미 전송된 요청은 완료될 수 있으며 성공 결과는 기존 체크포인트에 보존된다.
- 생성·독립 검증·제목 생성 중 계정 오류는 단계 중단으로 전파한다. 빈 평가 결과나 미검증 성공으로 변환하지 않는다. 생성 또는 검증 중 중단된 노드 기록은 `FAILED`로 종료한다.
- 사용자 알림에 잔액 충전 또는 인증·권한 점검이 필요함을 명시한다. 공급자의 원문 오류나 계정 정보는 알림 문구에 포함하지 않는다.
- HTTP 실패도 요청 이력에 상태 코드와 소요 시간을 기록하고 실제 요청 횟수를 집계한다. 이전 시도에서 사용한 토큰·비용도 유지한다.
- 이어서 실행하면 오류 상태를 초기화하고 완료된 노드·역질의 답변·직군별 평가 체크포인트를 재사용한다.
- 한 실행의 발명원리 적용(`s5_track_a`) 이력에서 4,000토큰 잘림이 19회 확인되어 `solutions.track_a_max_tokens`를 8,000으로 설정했다. 원리 수와 메커니즘·조건·검증 항목은 유지한다.

검증: 모델 SDK를 대체한 재현 테스트로 계정 오류 단일 호출, 병렬 대기 요청 차단, 분리된 해결 트랙 간 오류 공유, 검증 실패 시 커밋 금지, 알림 사유, 충전 후 체크포인트 재개, 직군별 미완료 응답만 재개, 잘림 후 사용량 집계를 확인했다. 전체 백엔드 테스트 316건 통과. 실제 공급자 잔액 충전 여부와 충전 뒤 솔루션 품질은 별도의 운영 확인 사항이다.

운영 중단 건의 알림 문구는 마지막 실패가 402인 경우에만 실행 잠금과 백업을 거쳐 갱신한다. 단계 위치·입력·해결안·평가·보고서·비용 이력은 유지하며, 계정 잔액이 부족한 동안 전체 분석을 반복 실행하지 않는다.
